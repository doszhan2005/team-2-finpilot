# FinPilot — Жеке қаржыны басқару жүйесі

## 1. Жоба туралы

**FinPilot** — пайдаланушылардың жеке қаржысын басқаруға арналған мобильді қосымша.

Қосымша арқылы пайдаланушылар күнделікті кірістері мен шығыстарын тіркеп, жеке бюджетін жоспарлап, қаржылық статистикасын бақылай алады.

Жоба Android мобильді қосымшасы, Laravel REST API сервері және MySQL дерекқоры негізінде әзірленеді.

## 2. Жобаның мақсаты

Жобаның негізгі мақсаты — пайдаланушыларға жеке қаржысын тиімді басқаруға көмектесетін ыңғайлы әрі функционалды мобильді қосымша әзірлеу.

**Негізгі міндеттер:**

- Кірістер мен шығыстарды есепке алу;
- Жеке бюджетті жоспарлау;
- Қаржылық операциялар тарихын сақтау;
- Шығындарды санаттар бойынша бөлу;
- Қаржылық статистиканы көрсету;
- Пайдаланушы деректерінің қауіпсіздігін қамтамасыз ету.

## 3. Проблема

Қазіргі уақытта көптеген адамдар жеке қаржысын басқаруда қиындықтарға кездеседі.

**Негізгі мәселелер:**

- Күнделікті кірістер мен шығыстарды бақыламау;
- Жеке бюджетті дұрыс жоспарламау;
- Артық шығындарды анықтай алмау;
- Қаржылық ақпараттың әртүрлі жерде сақталуы;
- Жалпы қаржылық жағдайды толық бақылай алмау.

**Шешімі:** Осы мәселелерді шешу мақсатында FinPilot мобильді қосымшасы әзірленеді. Қосымша пайдаланушыларға кірістер мен шығыстарды есепке алуға, бюджетті жоспарлауға және қаржылық статистиканы бақылауға мүмкіндік береді.

FinPilot қосымшасында келесі функцияларды іске асыру жоспарланған:

1. Пайдаланушыны тіркеу және жүйеге кіру.
2. Кірістерді қосу, өзгерту және жою.
3. Шығыстарды қосу, өзгерту және жою.

5. Айлық бюджетті жоспарлау.
6. Қаржылық статистиканы көрсету.
7. Кірістер мен шығыстар тарихын қарау.
8. Пайдаланушы профилін басқару.

## 7. Жүйе архитектурасы

FinPilot жүйесі үш негізгі компоненттен тұрады:

### 1. Android мобильді қосымшасы (Java)

- Пайдаланушы интерфейсін қамтамасыз етеді;
- Кірістер мен шығыстарды енгізуге мүмкіндік береді;
- Қаржылық ақпаратты экранда көрсетеді;
- Retrofit арқылы серверге сұраныс жібереді.

### 2. Laravel REST API сервері (PHP)

- Android қосымшасынан келген сұраныстарды өңдейді;
- Пайдаланушыларды тіркеу және авторизациялау логикасын орындайды;
- Қаржылық операцияларды басқарады;
- MySQL дерекқорымен байланысады;
- Нәтижені JSON форматында қайтарады.

### 3. MySQL дерекқоры

- Пайдаланушылар туралы ақпаратты сақтайды;
- Кірістер мен шығыстарды сақтайды;
- Бюджеттер мен қаржылық санаттарды сақтайды;
- Операциялар тарихын жүргізеді.

### Жүйенің жұмыс істеу схемасы

Android (Java) → Retrofit → REST API → Laravel (PHP) → MySQL

Мобильді қосымша серверге REST API арқылы сұраныс жібереді. Laravel сервері PHP тілінде сұранысты өңдеп, MySQL дерекқорымен байланысады және нәтижені JSON форматында мобильді қосымшаға қайтарады.

## 8. Design Patterns — Жобалау үлгілері

FinPilot жобасында бағдарламалық архитектураны жақсарту, кодты қайта пайдалануды жеңілдету және жүйені кеңейту мақсатында келесі алты жобалау үлгісін қолдану жоспарланған:

| Pattern | Қолданылуы |
|---|---|
| Repository | Деректермен жұмыс істеу логикасын бөлу |
| Adapter | API деректерін қосымшаға қажетті форматқа түрлендіру |
| Strategy | Қаржылық есептеудің әртүрлі алгоритмдерін қолдану |
| Builder | Қаржылық есептерді кезең-кезеңімен құрастыру |
| Memento | Бюджеттің алдыңғы күйін сақтау және қалпына келтіру |
| Observer | Деректер өзгергенде мобильді интерфейсті жаңарту |

### 1. Repository Pattern

Дерекқормен жұмыс істеу операцияларын негізгі бизнес-логикадан бөлу үшін қолданылады.

### 2. Adapter Pattern

REST API арқылы алынған деректерді Android қосымшасында қолданылатын модельдерге сәйкестендіреді.

### 3. Strategy Pattern

Күнделікті, айлық және жылдық қаржылық статистиканы әртүрлі есептеу алгоритмдері арқылы жүзеге асырады.

### 4. Builder Pattern

Қаржылық есептерді қажетті параметрлер бойынша кезең-кезеңімен қалыптастырады.

### 5. Memento Pattern

Бюджет параметрлерінің алдыңғы күйін сақтап, қажет болған жағдайда қалпына келтіруге мүмкіндік береді.

### 6. Observer Pattern

Қаржылық деректер өзгерген кезде Android интерфейсін автоматты жаңарту үшін қолданылады. Java ортасында Observer немесе LiveData механизмдері пайдаланылуы мүмкін.

**Жобалау үлгілерінің топтары:**

- Creational — Builder;
- Structural — Adapter;
- Behavioral — Strategy, Memento, Observer;
- Architectural — Repository.

## 9. Деректер базасы

MySQL дерекқорында келесі негізгі кестелерді құру жоспарланған:

| Кесте | Мақсаты |
|---|---|
| users | Пайдаланушылар |
| roles | Пайдаланушы рөлдері |
| transactions | Қаржылық операциялар |
| categories | Кіріс және шығыс санаттары |
| budgets | Жеке бюджеттер |
| budget_categories | Бюджет пен санат арасындағы байланыс |

Кестелер арасында 1:N және M:N байланыстары қарастырылады.

### MySQL

### GitHub

Команда мүшелерінің кодпен бірлесіп жұмыс істеуіне, өзгерістерді бақылауға және Pull Request арқылы біріктіруге арналған.

### Postman

REST API сұраныстары мен жауаптарын тексеру үшін қолданылады.

## 11. GitHub жұмыс тәртібі

Команда GitHub арқылы бірлесіп жұмыс істейді.

**Негізгі ережелер:**

1. `main` тармағы қорғалады.
2. Әр тапсырма жеке branch ішінде орындалады.
3. Өзгерістер commit арқылы сақталады.
4. Код GitHub репозиторийіне push арқылы жіберіледі.
5. Өзгерістер Pull Request арқылы ұсынылады.
6. Pull Request кемінде бір команда мүшесінің тексеруінен өтеді.
7. Мақұлданған өзгерістер `main` тармағына біріктіріледі.
